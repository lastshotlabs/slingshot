## Backend conformance

Framework contributors can verify config-driven entity semantics through the public
`@lastshotlabs/slingshot-entity/testing` entry point. `runEntityConformance()` runs one frozen,
backend-independent catalog, while the memory, temporary-file SQLite, live PostgreSQL, and live
MongoDB and Redis drivers select cases only from their immutable capability profiles. PostgreSQL uses
`TEST_POSTGRES_URL` with a unique schema per harness; MongoDB uses `TEST_MONGO_URL` with a unique
database per harness; Redis uses `TEST_REDIS_URL` with a random validated key prefix. Results are
serializable passes, profile-derived skips, or sanitized
failures; unsupported operation configurations still fail during bootstrap.

CI publishes the ephemeral five-store JSON report, while the committed
[entity backend support matrix](/reference/entity-backend-support/) is generated from the stable
profiles.

Runtime SQLite and PostgreSQL entity bootstrap also reconciles framework-managed index definitions:
indexes use stable names derived from their ordered fields and uniqueness, and bootstrap removes
legacy positional names after creating the current definition. PostgreSQL tenant-scoped unique
indexes treat `NULL` tenant values as equal, so global rows cannot bypass uniqueness. PostgreSQL CRUD
statements quote generated column identifiers, so schema fields such as `order` remain valid.

Generated and config-driven `list()` implementations share the same consumer contract across
backends: pagination follows the configured default sort plus deterministic cursor tie-breakers,
nested filters support comparison, membership, containment, and logical operators, and a requested
limit above the configured maximum is rejected rather than silently truncated. Callers that need to
scan a full collection must follow `nextCursor` in bounded pages.

Soft-deleted rows remain hidden by default. Trusted application code can explicitly request them
with `adapter.list({ includeDeleted: true })`; the option is implemented consistently by memory,
SQLite, PostgreSQL, MongoDB, and Redis adapters. Generated HTTP list schemas do not expose this
switch automatically, because restoring or auditing deleted records requires an application-owned
authorization boundary.

## Why this changed

`Config-driven` was too broad. It mixed:

- package authoring
- entity authoring
- route policy
- storage wiring
- escape hatches

That made it harder for users to answer basic questions like:

- how do I scaffold an app?
- where is the normal package story?
- where is the normal entity story?
- where do the advanced customizations begin?

The new split makes those paths explicit.
